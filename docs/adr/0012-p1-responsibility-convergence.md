# ADR 0002：P1 职责收敛清理

- 状态：已接受
- 日期：2026-09-15
- 范围：FUSE 门控、策略缓存、Xposed 入口瘦身

## 背景

P0 热路径优化完成后，P1 阶段处理职责不清与噪声过大的遗留问题。

第一，`FuseJavaGate` 曾采用严格门控，真机观测到 26 个已 Hook 方法与 13 个未知方法，伴随两起误伤：嵌套类删除桥接实际走真实方法，插入 Lambda 实际走外部入口，均被严格门控误拦。

第二，`HookPolicyCache` 把多领域策略放在同一快照里，各领域生命周期不同，刷新时机与失败语义互相牵制。

第三，`XposedInit` 承担过多装配职责，入口臃肿，重试语义散落在多处。

## 决策

1. **FuseJavaGate 改用 sanitizeRoles 宽容门控**：门控只拦截坏路径，不拦截未知路径。噪声收敛为 -1 并保留运行时回退。对照提交主题 `perf fuse gate`。
   - 两起误伤均已确认：嵌套类删除桥接经真实方法覆盖，插入 Lambda 经外部入口覆盖，均非坏路径，不应拦截。

2. **HookPolicyCache 按领域拆分持有者**：各领域独立持有、独立刷新、独立失败处理。对照提交主题 `refactor cache holders`。

3. **XposedInit 瘦身为 MediaProviderRuntime 启动器**：只保留 bootstrap 装配，重试语义原样保留并内聚到启动器内。对照提交主题 `refactor bootstrap`。

## 后果

- 真机未知方法噪声不再放大为拦截，误伤消除，坏路径依然被拦。
- 各领域缓存可独立演进，一处刷新失败不牵连其他领域。
- 入口可读性提升，重试行为不变，后续启动流程变更只改一处。
- 风险：宽容门控对真正未知坏路径的发现延后，依靠运行时回退与日志补位。

## 拒绝事项（含理由与证据）

1. **拒绝 HOT_PATH 双模式**：曾考虑为热路径再加一套双模式开关。拒绝理由是增益可忽略，证据是短路与缓存已覆盖主要开销，再加模式只增分支与测试负担。

2. **拒绝逐规则 need 门控**：曾考虑对每条规则加独立 need 门控。拒绝理由是过度设计，证据是当前策略门控已在入口收敛，逐规则门控会把调用量放大到规则数级别，复杂度与收益不成比例。

3. **拒绝新建 MediaPathResolver**：曾考虑新建统一路径解析器。拒绝理由是时机未到，决定延期。证据是现有 `(pkg, userId, path)` 重载与仿真前缀快路径已满足当前需求，新建抽象暂无稳定职责边界，强行新建只会增加一层转调。

## 附录

- 未归因 15:14 应用 FATAL：堆环在栈抓取前已轮转，且应用进程内未加载 Hook 代码，故无法归因到 Hook 变更，不作为回滚依据。
- DataBus E 级日志为既有 SELinux 预期：在受限域下部分总线文件访问被拒属于已知预期行为，与本次 P1 清理无关。
- 相关提交主题：`perf fuse gate`、`refactor cache holders`、`refactor bootstrap`。
- 真机数字为观测值：26 个已 Hook 方法、13 个未知方法均为设备上实际观测记录，未做推算放大。
