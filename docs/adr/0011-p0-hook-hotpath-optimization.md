# ADR 0001：P0 Hook 热路径优化

- 状态：已接受
- 日期：2026-09-15
- 范围：MediaProvider Hook 热路径（读、查、挂载点解析）

## 背景

MediaProvider 进程内的查询与挂载点解析处于高频调用路径。历史实现存在三处可观测问题。

第一，`HookDataBusBridge` 读取失败时的回退语义不一致。文档约定读失败走文件回退，但实现上 Binder 失败分支直接返回 null 或 0，没有进入文件回退，导致调用方看到空策略或零水位。

第二，`QueryHooker` 在每次查询上都走全量策略门控与反射查找，开销落在热路径上。冷启动阶段还出现过一起死锁事件：如果启动时以 `hasActiveSession` 作为门控，没有会话就没有查询，有查询才能建会话，首个会话永远建不出来。

第三，`getMountedPath` 使用正则做前缀匹配，每次调用都走正则引擎，不适合高频路径。

## 决策

1. **HookDataBusBridge 读回退对齐**：将 Binder 失败分支与文档约定对齐，失败后走文件回退，不再直接返回 null 或 0。对照提交主题 `fix bridge fallback`。

2. **QueryHooker 策略门控短路加反射缓存**：无拒绝、无记录标记、无重定向规则时直接短路返回，不进入重逻辑；反射查找结果缓存复用。对照提交主题 `perf query/path`。
   - 冷启动死锁修复：最初的 `hasActiveSession` 门控会阻止首个会话创建，已改为策略门控，只检查 `isDenied`、记录标记、`hasRedirectRules`。无相关策略时放行，首个会话可以正常建立，会话建立后再进入正常门控。

3. **getMountedPath 去正则**：以仿真前缀快路径替代正则，保留已有的 `(pkg, userId, path)` 重载用于精确匹配。对照提交主题 `perf query/path`。

## 后果

- 热路径上无策略请求的开销下降，查询与挂载点解析不再承担不必要的门控与正则开销。
- Binder 瞬时失败不再放大为全空策略，行为与文档一致。
- 冷启动首会话可正常创建，不再被门控卡死。
- 风险：短路条件依赖快照新鲜度，若快照滞后可能短暂放行。由 DataBus 信号游标与刷新机制覆盖，不在本 ADR 另加补偿。

## 拒绝事项（含理由与证据）

1. **拒绝 MediaProviderInternals 超级聚合中心**：曾考虑把查询、插入、挂载点解析收敛到一个 `MediaProviderInternals` 大枢纽。拒绝理由是该枢纽没有独立职责，只是把三个独立生命周期的调用集中转调，会形成新的耦合点。证据是现有三条路径的调用方、刷新时机、失败语义均不相同，强行聚合后任何一侧变更都会波及其他两侧。
